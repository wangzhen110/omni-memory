# 竞品与赛道定位

本页回答两个问题：全息记忆在 AI Memory 赛道里**现在处于什么位置**，以及**哪些比较是不成立的**。竞品信息按公开文档的定位整理，不代表对其最新版本的完整评测；本项目数字见 [BENCHMARKS.md](BENCHMARKS.md)。

## 1. 先分赛道

AI Memory 至少有三类不同产品，放在一张排行榜上没有意义：

1. **记忆基础设施**：Mem0、Zep/Graphiti、Supermemory 等，重点是抽取、存储、检索 API 和托管服务。
2. **有状态 Agent 运行时**：Letta（MemGPT）等，重点是 agent 自身的内存块、状态和运行时。
3. **宿主内记忆插件/本地 MCP 服务**：全息记忆、Basic Memory 一类，重点是装进已有 AI 宿主、数据留在本地、通过 MCP/CLI/HTTP 暴露工具。

全息记忆属于第 3 类，同时向第 1 类借了双时态事实、冲突标记、图检索这些能力；它**不是**一个替代 Mem0 或 Zep 的托管平台。

## 2. 维度对比

| 维度 | 全息记忆 | Mem0 | Zep / Graphiti | Letta (MemGPT) | 本地 MCP 记忆类 |
|---|---|---|---|---|---|
| 主要形态 | 本地 SQLite + MCP/HTTP/CLI 插件 | SDK + 托管 API | 托管服务 + 时序知识图 | 有状态 agent 运行时 | 本地文件/SQLite + MCP |
| 数据在哪里 | 本机 `OMNI_HOME` | 厂商云 / 自托管 | 厂商云 / 自托管 | 自托管运行时 | 本机 |
| 中文优先 | 是（CJK 二元组、中文金标） | 否（以英文生态为主） | 否 | 否 | 视项目而定 |
| 双时态事实 | 是（`valid_from` / `valid_to`） | 部分版本有历史 | 是（时序图） | 以内存块为主 | 少见 |
| 冲突处理 | 显式 `contested` + 搜索结果 flag | 以抽取/更新为主 | 以图边时序为主 | 以状态改写为主 | 少见 |
| 四层记忆 | 转录 / 笔记 / 事实 / 实体图 | 抽取记忆 + 向量/图 | 图 + 向量 | 内存块 + 归档 | 通常 1–2 层 |
| MCP 工具面 | 25 个 MCP 工具 | 有 SDK/框架集成 | 以 API/SDK 为主 | 以运行时为主 | 通常少量工具 |
| 项目 scope 隔离 | 显式 scope + 跨项目隔离测试 | 多租户/项目 | 多租户 | 运行时隔离 | 视实现 |
| 公开 QA 分数 | **无** | 有公开评测/榜单 | 有公开评测/榜单 | 有公开评测/榜单 | 通常无 |
| 许可证 | AGPL-3.0-only + 商业例外 | 开源 + 商业服务 | 开源/商业混合 | 开源 | 各异 |
| 社区规模 | 早期独立项目 | 大 | 大 | 大 | 小 |

## 3. 现在的水平

**在“本地优先 + 中文 + MCP 个人记忆”这个细分里**，全息记忆的功能密度是有竞争力的：

- 25 个 MCP 工具、21 条 loopback HTTP 路由、CLI 和 Web 面板共用同一个库。
- 四层记忆、双时态事实、冲突 contested、四路 RRF、本地语义、图检索、项目 scope 都在同一进程内闭环。
- 120 条确定性质量用例全过；LoCoMo session 粒度 evidence recall@10 0.7134；10M 字符规模检索 p95 6.9ms（100k 短笔记）。
- 数据默认留在本机，无外部 API key 也能跑。

**放到全球 AI Memory 主赛道**，它仍然是早期独立项目：

- 没有官方 LoCoMo/LongMemEval QA 分数；只有检索层自测。
- 没有真实用户规模、社区生态、第三方集成和独立复现。
- 没有 macOS 真机验收；Linux 只靠 CI，Windows 是当前开发机。
- 没有远程多租户鉴权；HTTP 是 loopback-only，不能当托管服务卖。
- 社区指标仍接近零；4.0.0 起许可证是 OSI 认可的 AGPL-3.0-only，但采用规模不会因为换许可证自动增长。

## 4. 不成立的比较

- 不能拿本项目 120 条确定性用例去对比 Mem0/Zep 的公开 QA 分数：数据、指标、judge 都不同。
- 不能拿 LoCoMo **检索** recall 去对比官方 LoCoMo **QA** 准确率：后者还包含答案生成。
- 不能因为工具数量多，就推断“比 Mem0 更强”：工具面是功能密度，不是采用规模或答案质量。
- 不能把“本地跑得快”当成“生产就绪”：还缺并发、备份恢复演练、远程鉴权和独立安全审计。

## 5. 结论

一句话：**在本地中文 MCP 记忆这个窄赛道里，它是一个功能完整、可自部署、测试较硬的自建制；在全球主赛道里，它仍是一个缺公开分数、缺用户、缺跨平台验收的早期项目。** 下一阶段的重点不是继续堆功能，而是把 C 类（官方 QA、真实用户、macOS 真机）补上；这些不能靠代码生成。
