## 4. 本轮问题清单

### 4.1 重要 — §4:55 的 4.6.7 基线数字与段覆盖结论写错

汇总 §4:55：「同口径 4.6.7 基线为 205/226」「可执行行由 210 降到 205」「段覆盖不变」。lcov 原生字段实测：

| 版本 | LF | LH | 并集 | 180-228 段 | 207/208 |
|---|---:|---:|---:|---:|---|
| 4.6.7 | 226 | **214** | **214/226 = 94.69%** | 45/47 | 未覆盖 |
| 4.6.8 | 228 | 205 | 205/228 = 89.91% | 49/49 | 已覆盖 |

三处错：① `205/226` 是拿 4.6.8 分子配 4.6.7 分母；② `210` 无 4.6.7 依据（4.6.7 LH=214，210 是 4.6.8 早期草稿值）；③ 「段覆盖不变」不成立——本轮新增失败帧断言恰恰把 207/208 从未覆盖变成覆盖，是**提升**，与 §3 第 2 项自相矛盾。前一轮复核报告 §3.2 已正确写 214/226，重复出错说明缺 lcov LF/LH 直读环节。
**建议改为**：「4.6.7 基线 214/226（94.69%）；本轮 205/228；分母 +2、LH −9 源于错误回显改动与 157-162 回退；段覆盖由 45/47 提升至 49/49，207-208 由未覆盖转覆盖。」

### 4.2 建议 —「v1 盲区已闭」表述超出脚本能力

§1:10 称「v1 盲区本轮已闭」。`verify-release` 的 `manifestUrlForRelease` 仍优先取 v2，v1 资产错配不会让脚本失败。本轮能确认的是本地 v1 文件正确且签名有效、远端资产 id 已换（§8:6），但「盲区已闭」只能靠人工单独下载 v1 核对，不是脚本保证。建议改为「v1 资产已按 f0679f28 重签并人工回读；脚本盲区仍在，需单独核对 v1」。

### 4.3 建议 — 云主机证据性质需收紧

`4.6.8-vm.txt` 自述「只是摘要摘录，不是完整 TAP」，完整 TAP 在云主机 `/tmp/vm-4.6.8.tap`。因 `7de3539..f0679f2` 零源码改动，「代码未变故数字有效」的**推理成立**，但这是推断性证据，不是 f0679f2 在该机的实测；3 个 skip 的用例名也未列。建议表述改为「7de3539 摘录显示 540/537/0/3；与最终提交仅 docs 差异，推断结果不变，未在该机重跑完整 TAP」。可作辅助证据，不宜作门禁硬证据。

### 4.4 建议 — 错误回显行为变更未入 DESIGN

`DESIGN.md:10` 要求「行为变更先改本文并升版本，再改代码」。客户端可见报错文本改为固定 `internal error` 属可观察行为变更，现只在 CHANGELOG 与 Release 正文出现，汇总 §6:74 已标待定。风险低（下游断言可能依赖文案），建议本版补 DESIGN 条目或下版显式声明。

### 4.5 建议 — 1 条恒真断言残留

`test/entry-diagnostics-4.6.8.test.mjs:62` 的 `assert.equal(section.text({}).length >= 0, true)` 恒真，与该文件自称修掉的「原断言接近恒真」同类。建议转 4.6.9 或本轮补掉，否则自评与事实不符。

## 6. 待老板拍板：tag 移动策略

汇总 §6:74 把「docs-only 提交后是否继续移动 tag」列为待定。高见远（架构）评估：

- 前两次移动必要（修跨平台失败、修证据时序）；**后两次移动由 docs-only 触发**，`4dd011a`→`45011a4`→`f0679f28` 每次都重签 manifest + 换资产 id，并已催生 `02b77612` 无效 SHA 返工。
- 自问「改变玩家哪个决定」：**不改变**。玩家/客户端下载的代码字节（`b3f7e44e`、4.6.8）前后一致，变的只是 tag 溯源到的 commit 值。
- **建议**：docs-only 修正不再移动 tag，只更新 Release 正文与 CHANGELOG；tag 只在代码变更时移动。这样能去掉 manifest 重签 + 资产换 id 的重复成本，也消除 `02b77612` 这类返工来源。代价是 tag 指向的 commit 不含最后的文档修正——若接受这点，建议采纳。
