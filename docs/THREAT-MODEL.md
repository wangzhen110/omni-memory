# 威胁模型（Threat Model）

- 版本：1.1（2026-11-21）
- 适用：全息记忆（Omni Memory）DSH 插件 v3.9.5+
- 维护规则：**新增 HTTP 路由、写入路径、外部端点或 scope 规则时必须先更新本文件**，再改代码。

## 1. 资产

| 资产 | 位置 | 泄露/破坏后果 |
|---|---|---|
| 转录原文 | `$DSH_HOME/memory/omni.db` | 全部对话历史暴露 |
| 笔记/事实/画像 | 同上 | 模型被错误或恶意记忆持续影响 |
| 向量/图/bigram/语义索引 | 同上 | 检索失真，但不含额外原文 |
| 本地语义模型与 WASM 运行时 | 插件包内 `models/` + `lib/vendor/` | 文件被替换可执行任意推理逻辑；进程内 CPU 读取记忆正文 |
| HTTP 写能力（遗忘） | `127.0.0.1:<port>/omni-memory/*` | 记忆被静默删除 |
| 外部请求（可选） | `OMNI_EMBED_URL`、`OMNI_SCOPE_JUDGE` | 记忆正文离开本机 |

## 2. 参与者与信任边界

| 参与者 | 能力 | 信任级别 |
|---|---|---|
| 本机同一用户 | 读文件、读端口、起进程 | **不信任**（loopback 不是认证） |
| 本机其他用户 | 通常隔离，可能读共享目录 | 不信任 |
| 浏览器中的任意网页 | 可向 `127.0.0.1` 发简单请求、可加载 `<img>` | 不信任（CSRF 面） |
| 网络攻击者 | 无法直接访问 loopback | 不信任（依赖绑定地址） |
| 被读入的文档/网页内容 | 可诱导模型写入恶意笔记（memory poisoning） | 不信任 |
| 外部嵌入服务 | 收到发送的文本 | 仅当用户显式配置 `OMNI_EMBED_URL` |
| 复核模型 | 收到写入正文 | 仅当显式设置 `OMNI_SCOPE_JUDGE=auto/always` |

## 3. 现有控制

| 威胁 | 控制 | 位置 |
|---|---|---|
| 网络来源读取 | 绑定 loopback + `isLoopback` 校验 | 所有路由 |
| 浏览器 CSRF 删除 | 写操作仅 POST + `Origin`/`Host` 同源 + `x-omni-csrf: 1` | `mutationAllowed()` |
| 跨项目读取 | `scope` 过滤 + 裸请求默认 global + 工具上下文解析 + 未知上下文 fail-closed | `scopeClause` / `projectForScope`；FTS/向量采样后由 `scopeAllows` 在 JS 复核（ADR-020） |
| 历史状态污染 | 活跃读取统一排除 `superseded_by` / `valid_to` | 搜索/画像/图/节点/列表 |
| 模型空输出提升 scope | 空输出保留规则判定 | `flushJudge` |
| 默认上传正文 | `OMNI_SCOPE_JUDGE` 默认 `off`，README 明示 | `judgeMode()` |
| 本地语义默认外发 | 模型与 WASM 随包，进程内推理，默认不联网；只有显式 `OMNI_EMBED_URL` 才走远程 | `lib/semantic-embed.mjs` |
| 语义模型文件被篡改 | 发布闸门校验字节数；再分发保留许可文件；模型以普通文件随包，仍属本机信任边界 | `scripts/check-semantic-assets.mjs` |
| rerank 外发记忆正文 | 仅在显式配置 `OMNI_RERANK_*` 时发生；只发送 query + top-20 候选正文，支持自建端点 | `lib/rerank-provider.mjs` |
| 恶意笔记自动注入 | contested 不注入；自动召回只注入未替代、未争议的命中 | prompt section |
| 多步写入半截 | `BEGIN IMMEDIATE` 事务 | 写入/做梦/压缩/遗忘/导入 |
| 重启后语义静默失效 | 维度持久化 + 探针 + 回填 + `memory_reindex` | 远程嵌入生命周期 |
| 全量记忆被导出扩散 | 导出仅 loopback、需本机访问；文件落在 `$DSH_HOME/memory/`，明文与数据库同一边界 | `memory_export` / `/omni-memory/export` |
| 恶意备份注入记忆 | 导入只接受**本地文件路径**（工具参数），不做 HTTP 上传；默认 dry-run；合并去重 | `memory_import` |
| 误删无法挽回 | 墓碑保留 + 审计视图 + `memory_restore`（POST + CSRF） | 恢复链路 |
| 上游仓库被改写后投毒 | `daily-sync` 默认只报告；`--apply` 必须验 Ed25519 签名清单、固定公钥指纹、`package.json` 哈希、启动器哈希与签名提交谱系，只快进到签名提交；启动器安装到内容寻址路径后再切换任务 | 更新链（3.11.8） |

## 4. 明确不解决的问题（残余风险）

1. **同用户本机进程**可调用读接口获取全库；没有进程级凭据。写接口仅防浏览器跨站。
2. **数据库明文**，备份/同步/磁盘取证均可读。
3. **memory poisoning**：高置信恶意笔记仍可能被写入并被自动召回（已排除 contested/superseded，但没有人工审核队列）。
4. **远程端点信任**：配置了 `OMNI_EMBED_URL`/远程 `OMNI_EMBED_PROVIDER` 就把嵌入文本发给对方；配置 `OMNI_RERANK_*` 就把查询和候选正文发给对方。插件只负责说明，不负责对方的数据处理；敏感数据建议自建端点。
5. **画像预算**：正文加头部可能略超 1200 字（已按总长度截断，但不是严格 token 预算）。
6. **备份文件**：导出的是明文 JSON，包含全量原文；复制/同步/上传后无法追踪，也无法远程撤销。导入不校验来源，恶意备份等价于直接改库（本地信任边界内）。
7. **大库导出**：在请求线程内序列化，10 万行级别可能占用数秒内存；尚未流式化。
8. **本地语义内存**：模型常驻约 216MB RSS，低内存设备可能触发系统回收或加载失败；失败时降级为词面/hashed，不影响会话，但语义召回消失。
9. **模型供应链**：模型与 WASM 随包分发，完整性由发布闸门与包管理器校验；没有签名校验，能改写插件目录的本机攻击者也能替换模型。
10. **更新链残余**：公钥固定后没有在线撤销列表，私钥泄露只能手工分发新版本并轮换；清单签 `package.json` 哈希与提交谱系，不签整棵 tree；3.11.5 及更早没有签名校验。
11. **`npm run setup` 不是签名更新入口**：它只校验同提交 `package.json` 声明的启动器 SHA-256（防损坏/误改，不防被篡改的 fork）；Ed25519 验签只在 `daily-sync --apply`。从不可信镜像 clone 后运行 setup，风险等同于运行该镜像里的任意代码。

## 5. 新增路由/写路径的检查清单

- [ ] 路径不以 `/api` 开头（宿主保留前缀）
- [ ] 读：`isLoopback` 校验；写：POST + `mutationAllowed`
- [ ] 参数是否可能改变数据？若会，走 query string（宿主可能已读空 body）
- [ ] 返回是否泄露绝对路径/凭据？只返回 basename 与统计
- [ ] 是否有对应回归用例（含 403/405 与跨站场景）
- [ ] 是否更新本文件与 `docs/DESIGN.md` 的契约表

## 6. 复查触发条件

出现以下任一情况必须重新评审威胁模型：新增外部网络调用、新增写路由、新增存储字段承载原文、修改 scope 解析、引入第三方依赖、准备对外发布新版本。
